# 2026-08-07 강의 소스(src_0807.zip) 반영 기록

## 무엇을 했나

`src_0807.zip` (강사 배포 소스 스냅샷)을 현재 프로젝트 구조/네이밍에 맞춰 반영했다.
zip을 그대로 덮어쓰지 않고, 이미 완성돼 있던 기능(`features/blog` 의 posts CRUD,
`BlogCard`, `blogApi`, `HomePage` 등)은 그대로 두고, zip에만 있던 내용 중
**현재 프로젝트에서 미완성/깨진 상태로 남아있던 부분**만 zip을 참고해서 완성시켰다.

zip에 같이 들어있던 CRA 스캐폴딩 파일(`App.test.js`, `reportWebVitals.js`,
`setupTests.js`, `logo.svg`, `TestRouterApp.js`, `ToyApp.js`)은 현재 프로젝트에서
이미 정리된 상태였으므로(커밋 `1ae6492 fix: 앱 실행 불가 오류 수정 및 프로젝트 구조 정리`)
다시 들여오지 않았다.

## zip 소스의 중점이 어디에 있었나

zip 안의 `features/blog` (page/list/item 구조)를 기준으로 보면, 이 강의 회차는
아래 주제에 집중돼 있었다.

1. **게시글–댓글 1:N 관계를 json-server 로 다루기**
   - `api.get('/blogs/:id?_embed=comments')` 로 게시글과 댓글을 한 번의 요청으로 가져오는 패턴.
   - 댓글은 `postId`(zip 에서는 `blogId`) 외래키로 게시글과 연결.
   - 댓글 작성은 `POST /comments`, 삭제는 `DELETE /comments/:id` 후 배열에서 필터링.
2. **list/item 컴포넌트 분리 패턴**
   - `BlogList`/`BlogItem`, `BlogCommentList`/`BlogCommentItem` 처럼
     "목록은 순회만 담당하고, 실제 렌더링은 item 이 담당"하는 구조를 댓글에도 동일하게 적용.
3. **styled-components 로 재사용 가능한 UI 만들기**
   - `Button`, `TextInput` 을 공용 컴포넌트로 분리하고 `$active` 같은 transient prop 으로
     카테고리 칩(chip) UI, 로딩 스피너(keyframes) 등을 구현.
4. **localStorage 기반의 아주 단순한 로그인 상태 관리**
   - JWT/Spring Security는 "추후 작업"으로 주석만 남기고, 우선 `localStorage.getItem('user')`
     로 로그인 여부만 흉내내는 수준.
5. **useMemo 를 이용한 파생 상태 최적화**
   - 카테고리 필터링(`selectedCategory`)을 `useMemo` 로 감싸는 예시.

## 실제로 반영/수정한 파일

현재 프로젝트는 `posts` 컬렉션 기반 블로그(`features/blog/*`, react-bootstrap)가 이미
완성돼 있고, 그와 별도로 **댓글 실습용 샘플**(`pages/sample/BlogReadPage.jsx` +
`features/blog/item/BlogcommnetItem.jsx` + `features/blog/list/Blogcommentlist.jsx`)이
깨진 채로 남아 있었다. zip의 `BlogCommentItem`/`BlogCommentList`/`BlogReadPage` 로직을
참고해서 아래처럼 고쳤다 (필드명은 zip의 `blogId`/`email` 대신, 이미 존재하는
`posts` 스키마에 맞춰 `postId`/`writer` 로 맞췄다).

| 파일 | 문제 | 조치 |
|---|---|---|
| `src/features/blog/item/BlogcommnetItem.jsx` | 본문이 비어있어 아무것도 렌더링하지 않음 | 댓글(writer/comment) 렌더링 + 삭제 버튼 구현 |
| `src/features/blog/list/Blogcommentlist.jsx` | `styled-components` 오타(`styledcomponents`), item import 누락, 문법(들여쓰기) 오류 | import 수정, `onDelete` prop 전달 구조로 정리 |
| `src/pages/sample/BlogReadPage.jsx` | 미완성 JSX(정의되지 않은 `Button`/`navigate`), 파일 끝에 주석 처리 안 된 텍스트로 컴파일 자체가 깨짐 | `_embed=comments` 로 댓글까지 조회, 댓글 작성/삭제 핸들러, "글 없음" 분기 버튼 정상화 |
| `src/components/styled/TextInput.jsx` | 존재하지 않음 (zip에는 있음, 현재 `pages/sample/Textinput.jsx` 가 export 없이 미완성 상태로 방치돼 있었음) | `Button.jsx` 와 동일한 스타일로 신규 작성 |
| `src/App.jsx` | `SampleBlogReadPage` 를 import만 하고 라우트가 없어 죽은 코드였음 | `/samples/blog/:postId` 라우트 추가 |
| `db.json` | `comments` 컬렉션 자체가 없어서 위 기능이 동작 불가능했음 | `postId` 기반 `comments` 배열 추가 (post 1, 3에 시드 데이터) |

## 손대지 않은 것

- `src/pages/sample/Textinput.jsx`: 어디서도 import 되지 않는 미완성 파일. 삭제하면 진행 중이던
  작업을 잃을 수 있어 그대로 남겨뒀다. `components/styled/TextInput.jsx` 가 정식 대체품이니,
  필요 없다고 판단되면 이 파일은 지워도 된다.
- `features/user/Signinpage.jsx` / `Signuppage.jsx`, `features/blog/BlogWritePage.jsx` 등
  이미 완성돼 있던 기능들: zip 의 `styled-components` + `localStorage` 버전과 다른 방식
  (react-bootstrap + `userApi`/`blogApi`)으로 이미 구현돼 있어 손대지 않았다.

## 검증

- `CI=true npx react-scripts build` → 컴파일 성공 (구문 오류 없음).
- 임시 포트(4099)에 `json-server` 를 띄워 `GET /posts/1?_embed=comments`,
  `POST /comments`, `DELETE /comments/:id` 가 기대한 대로 동작하는 것을 확인.
- Playwright 등 브라우저 자동화 도구가 이 환경에 설치돼 있지 않아 실제 화면 스크린샷으로는
  확인하지 못했다. `npm run dev` (3004) + `npm run server` (4000) 를 띄운 뒤
  `http://localhost:3004/samples/blog/1` 에서 직접 확인해보는 것을 권장한다.
